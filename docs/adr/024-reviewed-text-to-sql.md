# ADR 024 — Reviewed text-to-SQL and grounded explanations

Accepted in Phase 5. Text-to-SQL remains the architecture; no embeddings, vector store or RAG arithmetic is introduced. The LLM returns a query key, actual parameterized SQL, parameters, answerability and confidence. Every financial sum, percentage, growth rate and volatility measure is calculated by PostgreSQL.

For the initial release, validation uses an exact allowlist of six complete reviewed SELECT query shapes: summary, monthly trends, weekly trends, fixed/variable costs, weekly volatility and observed provider totals. The selected SQL must match its registered statement after outer whitespace removal, and the date parameters must exactly match the dates explicitly selected by the user. The executor uses the registered statement and separately bound date values. It never executes untrusted SQL text. This is stricter and narrower than the parser-based free-form validation anticipated in ADR 008; adding a parser is unnecessary while no unreviewed expression is accepted.

Consequences: equivalent unregistered SQL, arbitrary joins, filters not represented by the catalog, specific-provider filtering, forecasts, causal claims and unsupported quantitative questions are refused. The interface lists the supported scope and shows the interpretation. This is bounded text-to-SQL, not a general-purpose SQL agent. Broader supported coverage requires reviewed catalog additions and tests. A model-reported confidence threshold is an extra refusal condition, not proof of semantic correctness; real-model evaluation is still required.

The question must be explicitly answerable with the selected date window. Low confidence, changed dates, unauthorized queries, invalid SQL, oversized results, inconsistent classification and missing/mixed currency lead to an explicit reliable-answer refusal. Results are capped at 100 rows; an oversized result is refused instead of silently truncated. Missing observations remain unknown. Monthly growth requires adjacent, fully selected calendar months and a positive prior revenue denominator. Provider output is labeled observed attributed net, never certified fully loaded contribution.

After query execution, the model receives the exact result and selects row/metric references. The application validates those references and renders constrained plain-language statements with the returned cells. It does not accept model-generated financial values or unrestricted numerical prose. This limits narrative richness but prevents invented numbers. SQL, bound parameters, raw results, interpretation and snapshot metadata accompany the answer.
